# PhishFinder dashboard

The frontend for PhishFinder. All frontend files live in this `dashboard` folder. It follows the official specification's `frontend/src` structure with the user-requested root name `dashboard`, and excludes the removed redirect-chain UI.

## Start

Requires Node.js 22.14+ and npm. Open `dashboard.code-workspace` in VS Code, then run:

```sh
npm install
npm run dev
```

Open http://127.0.0.1:5173/. The application always uses the analyzer API. Configure `ANALYZER_PROXY_TARGET` in `.env.local` if your analyzer runs somewhere other than http://127.0.0.1:8000. It must implement the contract in `docs/API-INTEGRATION.md`. An unavailable backend shows a retryable connection state and disables submissions; sample findings are never generated by the application. Legacy `mode` query parameters are removed automatically.

The development server and future edits use this repository's `frontend/dashboard` directory.

## What works

- Original `wallpaper2.jpg` background, `clownfish.png` logo, and Vista risk icons from `Joewuliu/Tripwired` on `main`, with glossy scan rows, glass controls, and exact creator credit. The wallpaper fills the frame proportionally without stretching. Decorative sky overlays and added slogans are removed.
- Compact URL submission with validation and inline errors. Suspect websites are never visited by this frontend.
- History search, time/risk/input/status filters combined with AND, five sort orders, 20-item pagination, URL-persisted filters, and first-page refresh while the tab is visible.
- Report routes at `/r/:scanId`, browser Back/Forward, hard refresh, native modal background isolation, explicit keyboard focus containment, Escape, and focus/scroll restoration. Reports use a lighter translucent Frutiger blue tint with a 16px blurred backdrop and an opaque fallback when blur is unsupported.
- Screenshot rail, enlarged raster view, capture timestamps and source, unavailable/expired states, non-clickable full defanged URLs, ordered check findings, evidence disclosures, partial/unknown/failed results, and score/coverage provenance.
- Parallel analyzer results presented in order, up to 1.5 seconds of educational pacing, reduced-motion bypass, and immediate provisional danger warnings.
- Final summary, recommended actions, copy-to-clipboard with manual fallback, FTC handoff to the fixed official destination, and server-backed rescan adapter.
- Analyzer-backed results, session-scoped caching, request cancellation, monotonic report revisions, bounded transport retries, CSRF and idempotency headers, Retry-After, and expired-session cache clearing.

## Analyzer connection

Completed reports show the summary above the evidence checks. The verdict and score appear once within the summary. When a running job finishes, the report returns to the top without moving keyboard focus. Rounded filters retain a glass focus rim, scan rows lift on hover, and local pixel hand cursors change over interactive controls on desktop. Text fields retain their text cursor.

The application requests the real analyzer endpoints described in `docs/API-INTEGRATION.md`. It does not generate findings or fall back to fixtures. The existing server remains responsible for the Python analyzer, Gemini calls, threat lookups, screenshots and sessions. The `src/demo` helpers are retained solely for automated test fixtures and are not imported by the application.

Copy `.env.example` to `.env.local` to configure the development proxy. `ANALYZER_PROXY_TARGET` is used by Vite's development server only. Provider credentials and signing secrets belong on the server.

API requests and response validation stay in `src/api`. Components never calculate live risk scores. Automated test fixtures stay in `src/demo` and are not used by the application. Styling is separated into tokens, reusable glass primitives, and page/responsive layout. All assets are local; no font, favicon, or image requests are made to scanned websites.

## Production serving

`npm run build` creates `dist/index.html`, hashed files in `dist/assets`, `dist/demo`, and `dist/.vite/manifest.json`. Serve the bundle through the analyzer at `/` and `/r/{id}`, preserving its existing `/analyze` endpoint. Read the manifest to insert hashed filenames into the provided Jinja shell. Production screenshots are served by the analyzer screenshot endpoint. The detailed route, header, session, and screenshot requirements are in [docs/API-INTEGRATION.md](docs/API-INTEGRATION.md).

Vite's development proxy does not exist in production. The analyzer/Caddy must serve same-origin `/api` endpoints and explicit report HTML routes. Unknown `/api` paths must return JSON 404, rather than the frontend HTML fallback.

## Verification and remaining integration

See [docs/ACCEPTANCE.md](docs/ACCEPTANCE.md) for checks and scope. The production build and browser tests validate the frontend, using real browser interactions and mocked server responses. They do not prove analyzer security, detector accuracy, durable job recovery, or deployed authorization. A manual screen-reader review and verification against the actual analyzer should precede production use.

Assets were retrieved from `Joewuliu/Tripwired` on `main`. They are stored unchanged in `public/icons` and copied to `dist/icons` by the build; serve `/icons` alongside `/assets`, `/cursors`, and the optional `/demo` files. This repository folder is the active editing location. Changes are local until committed and pushed.
